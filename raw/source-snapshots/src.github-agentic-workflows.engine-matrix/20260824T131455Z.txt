<p>Choose the engine that matches the required capabilities, identity mechanism, and existing provider access. Copilot supports the broadest engine-specific feature set, including native agent selection, custom harnesses, and continuation mode. Claude Code and Codex provide native web search when enabled. Gemini supports Google WIF and per-command bash restrictions. Pi supports multiple providers but requires proxy-specific tool configuration.</p>
<p>Changing engines requires updating <code dir="auto">engine:</code> and may also require different authentication, tools, model names, or network access. Review the setup guide and comparison before switching.</p>

<p>The <code dir="auto">api-target</code> field specifies a custom API endpoint hostname for the agentic engine. Use this when running workflows against GitHub Enterprise Cloud (GHEC), GitHub Enterprise Server (GHES), or any custom AI endpoint.</p>
<p>For a complete setup and debugging walkthrough for GHE Cloud with data residency, see <a href="/gh-aw/troubleshooting/debug-ghe/">Debugging GHE Cloud with Data Residency</a>.</p>
<p>The value must be a hostname only — no protocol or path (e.g., <code dir="auto">api.acme.ghe.com</code>, not <code dir="auto">https://api.acme.ghe.com/v1</code>). The field works with any engine.</p>

<p><code dir="auto">GITHUB_COPILOT_BASE_URL</code> is a fallback — if both it and <code dir="auto">engine.api-target</code> are set, <code dir="auto">engine.api-target</code> takes precedence.</p>
<p>When <code dir="auto">OPENAI_BASE_URL</code> or <code dir="auto">ANTHROPIC_BASE_URL</code> is set, the configured model is passed through to the custom provider verbatim: gh-aw automatically emits <code dir="auto">apiProxy.modelFallback.enabled: false</code> so the API proxy does not rewrite provider-specific model slugs (for example <code dir="auto">anthropic/claude-sonnet-5</code> on OpenRouter) that are absent from the built-in model catalog, which otherwise causes HTTP 404 <code dir="auto">model_not_found</code>. Set <a href="/gh-aw/reference/sandbox/#model-fallback-sandboxagentmodel-fallback"><code dir="auto">sandbox.agent.model-fallback</code></a> explicitly to override this default.</p>

<div class="sl-heading-wrapper level-h3"><h3 id="copilot-bring-your-own-key-byok-mode">Copilot Bring Your Own Key (BYOK) Mode</h3><a class="sl-anchor-link" href="#copilot-bring-your-own-key-byok-mode"><span aria-hidden="true" class="sl-anchor-icon"><svg width="16" height="16" viewBox="0 0 24 24" fill="currentColor"><path d="m12.11 15.39-3.88 3.88a2.52 2.52 0 0 1-3.5 0 2.47 2.47 0 0 1 0-3.5l3.88-3.88a1 1 0 1 0-1.42-1.42l-3.88 3.89a4.48 4.48 0 0 0 6.33 6.33l3.89-3.88a1 1 0 0 0-1.42-1.42m8.58-12.08a4.49 4.49 0 0 0-6.33 0l-3.89 3.88a1 1 0 1 0 1.42 1.42l3.88-3.88a2.52 2.52 0 0 1 3.5 0 2.47 2.47 0 0 1 0 3.5l-3.88 3.88a1 1 0 0 0 0 1.42 1 1 0 0 0 1.42 0l3.88-3.89a4.49 4.49 0 0 0 0-6.33M8.83 15.17a1 1 0 0 0 .71.29 1 1 0 0 0 .71-.29l4.92-4.92a1 1 0 1 0-1.42-1.42l-4.92 4.92a1 1 0 0 0 0 1.42"></path></svg></span><span class="sr-only" data-pagefind-ignore="">Section titled “Copilot Bring Your Own Key (BYOK) Mode”</span></a></div>
<p>The Copilot engine supports routing requests to an external LLM provider instead of GitHub’s default routing. This is useful when you want to use a different model or provider (e.g., OpenAI, Anthropic, Azure OpenAI, or a local Ollama/vLLM instance) while still using the Copilot CLI tooling.</p>
<p>Set <code dir="auto">COPILOT_PROVIDER_BASE_URL</code> in <code dir="auto">engine.env</code> to activate BYOK mode. The credential variables <code dir="auto">COPILOT_PROVIDER_BASE_URL</code>, <code dir="auto">COPILOT_PROVIDER_API_KEY</code>, and <code dir="auto">COPILOT_PROVIDER_BEARER_TOKEN</code> are explicitly allowed to carry <code dir="auto">${{ secrets.* }}</code> references in <code dir="auto">engine.env</code> under strict mode — they are not leaked to the agent container. Other <code dir="auto">COPILOT_PROVIDER_*</code> variables hold non-sensitive configuration and can be set as plain strings. When <code dir="auto">COPILOT_PROVIDER_BASE_URL</code> is a literal URL, gh-aw automatically adds its provider hostname to the AWF allow-list for both the main agent run and the threat-detection Copilot step, and the threat-detection step now derives its Copilot API target from that literal BYOK URL even when <code dir="auto">engine.api-target</code> and <code dir="auto">GITHUB_COPILOT_BASE_URL</code> are unset. When it is supplied via a secret or variable expression, add the provider hostname explicitly to <code dir="auto">network.allowed</code> so the threat-detection step can reuse that concrete host safely.</p>

<p>All five fields accept a literal integer or a GitHub Actions expression (e.g. <code dir="auto">${{ vars.MY_RETRIES }}</code>).
For <code dir="auto">watchdog-timeout</code>, the value is treated as seconds when it is a literal integer.

<p>The post-result watchdog is dormant until the harness observes a terminal safe output. <code dir="auto">noop</code> and ordinary task outputs such as comments, labels, pushes, and pull request creation are terminal; diagnostics such as <code dir="auto">missing_tool</code>, <code dir="auto">missing_data</code>, and <code dir="auto">report_incomplete</code> are not. Once armed, any stdout or stderr activity resets the inactivity clock. A quiet child process can still be terminated while it is doing useful work, and the harness may treat that termination as successful when a terminal safe output already exists.</p>
<p>You can also set the underlying <code dir="auto">GH_AW_HARNESS_*</code> env vars directly via <code dir="auto">engine.env</code> when you need expression-level control, including <code dir="auto">GH_AW_HARNESS_WATCHDOG_TIMEOUT_MS</code> for the post-result watchdog. Explicit <code dir="auto">engine.env</code> values take precedence over <code dir="auto">engine.harness</code> sub-key values. See <a href="/gh-aw/reference/environment-variables/#harness-settings-and-runtime-tuning-variables">Harness Settings and Runtime Tuning Variables</a> for supported env vars, units, clamping behavior, and engine-specific controls such as <code dir="auto">GH_AW_CLAUDE_STARTUP_RETRIES</code>.</p>
<p>Threat detection runs default <code dir="auto">max-retries</code> to <strong>0</strong> instead of inheriting the harness default of 3, since detection is a bounded scan of already-completed agent output rather than the primary task — a failed attempt should not silently retry the whole detection run and burn extra time and model spend. Set <code dir="auto">engine.harness.max-retries</code> (or <code dir="auto">safe-outputs.threat-detection.engine.harness.max-retries</code>) explicitly to opt back into retries for detection.</p>

<p>The specification defines the driver environment contract.
In SDK mode, gh-aw injects required runtime values:</p>
<ul>
<li><code dir="auto">GH_AW_PROMPT</code></li>
<li><code dir="auto">COPILOT_SDK_URI</code></li>
<li><code dir="auto">COPILOT_CONNECTION_TOKEN</code></li>
</ul>
<p><code dir="auto">COPILOT_MODEL</code> is required and must be set to the model to use
(e.g. <code dir="auto">gpt-4o</code>, <code dir="auto">claude-sonnet-4</code>). Drivers MUST fail fast when
it is not set.</p>
<p>For runtime controls, the driver should consume:</p>
<ul>
<li><code dir="auto">COPILOT_SDK_SEND_TIMEOUT_MS</code></li>
<li><code dir="auto">COPILOT_SDK_LOG_LEVEL</code></li>
</ul>
<p>In gh-aw, <code dir="auto">COPILOT_SDK_SEND_TIMEOUT_MS</code> is usually injected
automatically from workflow <code dir="auto">timeout-minutes</code> (via
<code dir="auto">GH_AW_TIMEOUT_MINUTES</code>) with safety headroom. Override it in
<code dir="auto">engine.env</code> only when you need a custom SDK send timeout.
<code dir="auto">COPILOT_SDK_LOG_LEVEL</code> is a host-provided driver control and
should be honored when gh-aw passes it to the driver process.</p>
<p>Do not set <code dir="auto">COPILOT_CONNECTION_TOKEN</code> manually. The harness
generates it per run and passes the same token to both the
sidecar and driver process.</p>

<p><code dir="auto">tools.timeout</code> limits how long any single tool invocation may run, in seconds. Useful when individual <code dir="auto">bash</code> commands (builds, test suites) take longer than an engine’s default:</p>

<p>Defaults: Claude <code dir="auto">60s</code>, Codex <code dir="auto">120s</code>. Other engines (Copilot, Gemini) are engine-managed and not enforced by gh-aw. See <a href="/gh-aw/reference/tools/#tool-timeout-configuration">Tool Timeout Configuration</a> for full documentation including <code dir="auto">tools.startup-timeout</code>.</p>

<div class="sl-heading-wrapper level-h2"><h2 id="claude-tool-enforcement-security-model">Claude Tool Enforcement Security Model</h2><a class="sl-anchor-link" href="#claude-tool-enforcement-security-model"><span aria-hidden="true" class="sl-anchor-icon"><svg width="16" height="16" viewBox="0 0 24 24" fill="currentColor"><path d="m12.11 15.39-3.88 3.88a2.52 2.52 0 0 1-3.5 0 2.47 2.47 0 0 1 0-3.5l3.88-3.88a1 1 0 1 0-1.42-1.42l-3.88 3.89a4.48 4.48 0 0 0 6.33 6.33l3.89-3.88a1 1 0 0 0-1.42-1.42m8.58-12.08a4.49 4.49 0 0 0-6.33 0l-3.89 3.88a1 1 0 1 0 1.42 1.42l3.88-3.88a2.52 2.52 0 0 1 3.5 0 2.47 2.47 0 0 1 0 3.5l-3.88 3.88a1 1 0 0 0 0 1.42 1 1 0 0 0 1.42 0l3.88-3.89a4.49 4.49 0 0 0 0-6.33M8.83 15.17a1 1 0 0 0 .71.29 1 1 0 0 0 .71-.29l4.92-4.92a1 1 0 1 0-1.42-1.42l-4.92 4.92a1 1 0 0 0 0 1.42"></path></svg></span><span class="sr-only" data-pagefind-ignore="">Section titled “Claude Tool Enforcement Security Model”</span></a></div>
<p>Claude Code accepts a <code dir="auto">--permission-mode</code> flag that determines whether the declared <code dir="auto">tools:</code> allowlist is enforced. Set <code dir="auto">engine.permission-mode</code> to one of <code dir="auto">auto</code>, <code dir="auto">acceptEdits</code>, <code dir="auto">plan</code>, or <code dir="auto">bypassPermissions</code>:</p>
<div class="expressive-code"><figure class="frame not-content"><figcaption class="header"></figcaption><pre data-language="yaml" class="wrap" style="--ecMaxLine:23ch"><code><div class="ec-line"><div class="code"><span style="--0:#7FDBCA;--1:#111111">engine</span><span style="--0:#D6DEEB;--1:#403F53">:</span></div></div><div class="ec-line" style="--ecIndent:2ch"><div class="code"><span class="indent">  </span><span style="--0:#7FDBCA;--1:#111111">id</span><span style="--0:#D6DEEB;--1:#403F53">: </span><span style="--0:#ECC48D;--1:#3B61B0">claude</span></div></div><div class="ec-line" style="--ecIndent:2ch"><div class="code"><span class="indent">  </span><span style="--0:#7FDBCA;--1:#111111">permission-mode</span><span style="--0:#D6DEEB;--1:#403F53">: </span><span style="--0:#ECC48D;--1:#3B61B0">auto</span></div></div></code></pre><div class="copy"><div aria-live="polite"></div><button title="Copy to clipboard" data-copied="Copied!" data-code="engine:  id: claude  permission-mode: auto"><div></div></button></div></figure></div>
<p><code dir="auto">engine.permission-mode</code> takes precedence over any <code dir="auto">--permission-mode</code> flag supplied through <code dir="auto">engine.args</code>. When unset, the default is <code dir="auto">acceptEdits</code> (or <code dir="auto">auto</code> when <code dir="auto">tools.edit: false</code>). gh-aw <strong>does not</strong> derive <code dir="auto">bypassPermissions</code> implicitly from unrestricted bash — set it explicitly.</p>
